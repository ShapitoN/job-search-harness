# Telegram — отправка первого сообщения делает оркестратор в Telegram Web

Агент `outreach` ГОТОВИТ сообщение: файл с текстом + блок в логе:

```
TG-ЦЕЛЬ: @username | Компания | повод: холодное / ответ на вакансию
ТЕКСТ: data/log/<дата>-outreach-tg/<username>.txt
РЕЗЮМЕ: <путь к PDF>
ПРОВЕРКИ: ledger find/touched — чисто; чёрный список — чисто
```

Отправляешь ты, в Telegram Web (web.telegram.org/k/), четыре шага. Скрипты — `bin/browser/tg_*.js`
(выполнять через javascript-инструмент браузера, описание — в шапке каждого файла):

1. `tg_peer_check.js` — **какой чат реально открыт**. Смена адреса `#@username` НЕ переключает
   чат: открывать только с полной перезагрузкой страницы, подождать, проверить. Иначе текст уйдёт не
   тому человеку.
2. `tg_insert_text.js` — вставить многострочный текст, **не отправляя**. Печатать клавишами нельзя:
   Enter в тексте отправит сообщение и разорвёт письмо.
3. Отправить (Enter), затем `tg_paste_file.js` — прикрепить PDF резюме (поле ввода перед этим
   должно быть пустым, иначе файл заберёт текст в подпись).
4. `tg_verify_sent.js` — единственное доказательство доставки: исходящие пузыри в открытом чате
   (текст и PDF с нужным именем). Клик и исчезновение окна доказательством не являются.

Только после шага 4 — `ledger.py mark-sent <компания> --channel telegram`.

Ограничения: окно отправки — рабочие часы получателя; новых контактов не больше 3–5 в сутки на
аккаунт; ответ не ждём и диалог не ведём (это `replier`). Вопрос про деньги, время созвона, тестовое
или личные данные — пользователю.
