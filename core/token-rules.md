# Экономия контекста — жёсткие правила

Нарушение любого пункта — авария, а не неоптимальность.

## Почему
Каждый вызов инструмента пересылает модели весь накопленный контекст заново — не раз за ход,
а раз за вызов. Стоимость файла в контексте = его размер × число вызовов после него.
Поэтому длинный агент дорожает не линейно, а квадратично: три агента по 55 вызовов стоят
заметно меньше одного на 165.

## Запрещено
1. **Печатать base64 в контекст** (вложения письма, изображения). Вложения кодирует на диске
   `bin/send_email.py`, в контекст возвращается одна строка.
2. **Вкладывать файлы через почтовый MCP-коннектор** — резюме на 300 КБ стоит сотни тысяч токенов.
3. **WebFetch собственных страниц и артефактов** — возвращается весь сырой HTML.
4. **Читать PDF повторно.** Один раз `pdftotext` в .txt, дальше работать с текстом.
5. **Выводить файл после записи «для проверки».** Write/Edit падают с ошибкой, если запись не
   прошла; отсутствие ошибки и есть подтверждение.
6. **Читать транскрипты субагентов** (`*.jsonl`, `tasks/*.output`). Только размеры через `ls`.

## Обязательно
- **Ограничивать вывод каждого вызова:** `head -c 4000`, `head -40`, `| wc -l`. Никаких `cat`
  больших файлов и `curl` без ограничителя.
- **Разбирать HTML на диске, не в контексте:** `curl -s URL | python3 parser.py` — в контекст
  попадает результат разбора, а не страница. Для этого и написаны `bin/scan_*.py`.
- **Бюджет считается в вызовах инструментов — во всех:** чтение файлов, grep и запись отчёта
  тоже вызовы. Воркеру задают потолок «N вызовов инструментов, включая чтение файлов» и
  контрольную точку на 70%. Достиг 80% — дописал отчёт, вышел.
- **Результат писать инкрементально**, после каждой единицы работы (источника, письма,
  находки), а не в конце. Отчёт оркестратору может не дойти, файл на диске — единственная
  гарантия.
- **Механику отдавать скриптам** (`bin/`): журнал, отправка, сканирование. Модель оценивает
  готовую таблицу, а не ходит по страницам.

## Не больше двух агентов одновременно
Веер из четырёх параллельных агентов легко упирается в лимит сессии: все умирают, не записав
ничего. Два региона — две пары подряд, а не четыре разом.

## Когда начинать новую сессию
- разговор идёт больше 3–4 часов;
- в контекст попадали изображения или PDF;
- третий-четвёртый круг одной и той же задачи.

Всё состояние живёт в файлах. Новой сессии достаточно прочитать `README.md` и `STATE.md`.
Начинать новую сессию каждый день — это норма, а не сбой.
